# Buff 只读表达式与圣遗物Count

## 支持范围

Buff / Debuff 的 Param1 支持数字、正负号、四则运算、括号、武器 `Index(n)`、`Count(状态ID2)`。

例如：`0.06 * Count(ST_Artifact_453805)`。

Count 读取本 Buff 施放者身上对应 Count 状态的 `RuntimeValue`；圣遗物初始状态的施放者就是穿戴者。`Count(Self,状态ID2)` 与上述写法等价。尚不支持读取任意目标、其他属性、min/max 或脚本调用。数字和 Index 原有写法仍可用。

已定义为 Count 但尚未施加、已经移除或未激活时读取0；错误的ID、非Count类型或缺少来源角色会报错。读取不创建状态、不增加或扣除次数、不取随机、不限制Count自身数值、不写回面板。除零、非有限数、错误语法和过深嵌套不能作为有效结果。

攻击、暴击率、角色直伤增伤、抗性、治疗/受治疗、两处反应加成、敌人增伤均使用同一读取入口。保留各路径原有叠层和取值时点，没有把所有属性改成逐hit刷新。APCost与GainEnergy等其他效果类型不因此获得表达式功能。

## 公共生命之契与夜魂Count

公共状态定义位于Charts/StatusData_Overall.xlsx的StatusData_Overall_Main。40009 / ST_BondOfLife标为Count并登记处理器，余额和增减仍用float，保留治疗抵扣的小数，不改变原有归零移除与无公共比例上限规则。新增40010 / ST_NightSoul，使用真正int余额，每个目标实例独立保存本人的上限，不新增角色上限表，也不在共享状态定义里写某个角色的上限。

夜魂配表示例（80和20仅为示例数字，不对应任何角色）：

| EffectType | Param1 | Param2 | TargetType |
| --- | --- | --- | --- |
| ApplyStatus | ST_NightSoul | 80 | Self |
| NightSoul | 20 | 留空 | Self |
| NightSoul | -1 | 留空 | Self |

第一行仅创建余额0、下限0、上限80的本角色夜魂池，不赠送点数。第二、三行分别增加20、扣除1点。夜魂上限及增减量只接受int文本，拒绝小数、浮点科学计数法、任意公式和Index写法，不自动取整；上限不能省略、不能为负数，可以填0。普通非夜魂ApplyStatus不受此Param2规则影响。

再次ApplyStatus同一个夜魂ID，只把此目标的上限改为本次Param2；已有余额保留，超过新上限时截至新上限，不清空或自动补满。NightSoul效果只改变余额，不改变上限；余额钳制在0到本实例上限之间，计算中使用long承接int相加后再钳制，避免溢出。归零仍保留已配置的夜魂池。若尚未ApplyStatus配置池便使用NightSoul增减，会明确报错，不猜测或默认角色上限。群体NightSoul效果在整批目标均确认有已配置池后才提交，同一目标不重复处理。

角色技能、状态效果（含武器/圣遗物）和敌方技能的ApplyStatus均已传递Param2，NightSoul效果也接入相应执行路径与加载校验。公共数值ID40009/40010在施加路径可解析为对应公共字符串ID，不会被武器或圣遗物局部前缀误改写。夜魂只能挂在实体，不能作为场地数值池。夜魂是公共点数资源，不自动代表夜魂加持、不自动触发夜魂迸发，也不在普通回合阶段自动消耗；角色专用机制另行管理。554及之后套装仍未续配。

### 公共ID的归属

公共ID只确定数值种类，实例的查找键实际为“具体角色＋状态ID”。`Count(ST_NightSoul)`及`Count(Self,ST_NightSoul)`均读取当前Buff的Caster身上的此池，四名角色同ID不会互相加总、取最大或随机取一个；无实例时为0。生命之契同理：`Count(ST_BondOfLife)`读取当前Buff施放者本人的浮点余额。A给B施加的Buff仍读施放者A，而不是宿主B；不能把这个约定暗改成读取受益人。

增减效果的目标则由TargetType与既有目标解析规则选出。角色给自己施加夜魂或增减本人余额时明确填写Self。不要把“公式读取谁”和“效果改动谁”混为一件事：已有BondOfLife效果公式中，无前缀的BondOfLife变量读施放者，Target.BondOfLife读当前目标；本次没有更改这个规则。

普通Count与生命之契继续使用原有float运行时读写。夜魂余额另有int唯一存储，旧RuntimeValue仅提供整数余额的浮点只读视图以兼容Buff公式，禁止经该float入口写夜魂，避免小数取整或大整数先丢精度后再扣点；写入夜魂统一走整数接口。原有序列化float字段保留迁移标记。
