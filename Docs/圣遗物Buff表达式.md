# Buff 只读表达式与圣遗物Count

## 支持范围

本文的`Count(...)`是Buff只读函数。`EffectType=Count`用于主动修改余额，Param1填状态ID、Param2填增减数/full/clear，两者不共用语法。主动效果已用于雷泽与香菱的三个计数，尚未迁移现有圣遗物计数；具体接入与重施区别见[Count效果接口](../codex_files/Count效果接口.md)。数值归零不自动删除状态，需要结束时另配RemoveStatus及触发条件。

Buff / Debuff 的 Param1 支持数字、正负号、四则运算、括号、`min(a,b)`、武器 `Index(n)`、`Count(状态ID2)`。科学计数法数字仍可用。

例如：`0.06 * Count(ST_Artifact_453805)`。

Count 读取本 Buff 施放者身上对应 Count 状态的 `RuntimeValue`；圣遗物初始状态的施放者就是穿戴者。`Count(Self,状态ID2)` 与上述写法等价。除下述明确开放的充能变量外，不支持读取任意目标、其他属性、max 或脚本调用。数字和 Index 原有写法仍可用。

537绝缘的爆发增伤已支持 `min(0.75,0.25*TotalRechargeRate)`。这里的 `TotalRechargeRate` 读取本状态施放者的 `GetFinalRechargeRate()`，包含有效RechargeBonus，100%写作1.0；不取共享Buff受益者的充能，不缓存成固定25%，不修改面板或能量。当前只允许MultiplierPart=DMGBonus读取此变量；充能Buff或其他乘区自读会明确报错，避免GetFinalRechargeRate递归。没有将本变量开放给其他效果类型。

已定义为 Count 但尚未施加、已经移除或未激活时读取0；错误的ID、非Count类型或缺少来源角色会报错。读取不创建状态、不增加或扣除次数、不取随机、不限制Count自身数值、不写回面板。除零、非有限数、错误语法和过深嵌套不能作为有效结果。

攻击、暴击率、角色直伤增伤、抗性、治疗/受治疗、两处反应加成、敌人增伤均使用同一读取入口。保留各路径原有叠层和取值时点，没有把所有属性改成逐hit刷新。APCost与GainEnergy等其他效果类型不因此获得表达式功能。

## 反应独立乘区读取

反应收集器支持月曜/Lunar与星烁/Stellar总类，并与已定义的具体反应名、真实伤害元素共同筛选。BaseDMGBonus、LunarDMGBonus、StellarDMGBonus分别返回，不能混入普通DMGBonus。主状态和效果行的ScriptHook都要通过，Count仍只读当前施放者数值，状态MaxCount规则不变。来源快照保存各独立乘区，后续Count变化不改写旧快照。

此处是数值接口支持，不等于已经实现真实月曜/星烁伤害流程。522超激化与523蒸发/融化的BaseDMGBonus落点已经用户确认并接入：超激化为`[SkillBaseDMG + QuickenCoeff × (1 + EMcoeff3 + BaseDMGBonus)] × 原后续乘区`；蒸发/融化为`TotalDMG × ReactionMultiplier × (1 + EMcoeff1 + BaseDMGBonus)`。不是给整个技能基础伤害另乘最终系数；原反应筛选仍有效，敌人公式不变。专用读取只处理BaseDMGBonus，不额外求值无关乘区条件；来源快照覆盖时沿用已保存值。星扩散按用户要求先跳过。

## 519 翠绿之影：扩散减抗目标

普通扩散减抗只施加给真正受到该次扩散伤害的敌人。相邻敌人仅接到传播元素、没有受到扩散伤害时不施加。45190401～04从本次实际伤害声明读取火/水/雷/冰元素，45190410只返回该受伤敌人，不用反应原点推算邻位或全场。由护盾承受的正数扩散伤害也计入；零伤害、其他元素直伤、其他反应派生伤害及队友扩散不计入。

伤害批次先提交，原ApplyStatus行动随后施加40%对应元素减抗，持续3回合，同名覆盖不叠加。不修改触发本次响应的既有伤害。普通ReactionTriggered(Swirl)通知不另外施加第二次，具体伤害声明按EventId去重。装备者阵亡时该来源减抗一起清理。星扩散分支仍待真实反应实现，不以普通扩散代替。

### 每个hit的暴击率如何区分

现有ResolveFinalCriticalDamage在每个hit、每个实际受击目标上分别调用GetStatusCritRate，最终概率为Clamp(角色CritRate + WeaponCritRate + 本次适用状态暴击率, 0, 1)，然后独立抽取一次随机数。不把一个hit的暴击结果传给下个hit，也不把主目标结果传给溅射目标；日志复用同一次随机结果。

本套装只需提前快照“本hit本目标是否有这16%资格”，不是提前汇总全部暴击率，更不是在角色CritRate字段上反复加减16%。其他数值和概率型条件继续在既定最终暴击入口求值，不能为了记录或显示再抽一次随机。

例如其他来源合计40%暴击率，hit1开始无超导和领域，则该目标本次为40%；若hit1之后展开领域，hit2开始领域仍在，则hit2对所有敌人可计入16%，得到56%。没有领域时，同hit中原已超导的目标可为56%，其他目标仍为40%，各自再独立抽随机。即使两次概率相同，暴击结果也不一定相同。

普通反应实时计算和来源快照使用有效精通；已经捕获的持续反应及SourceSnapshotOverride不重新查询状态。普通超导多目标伤害和减抗状态共用一次来源快照。读取TotalEM的既有武器基础加算、生命之契公式及月兆档位同步使用有效精通。Based回能使用有效充能，Flat不受影响；原前后台、元素系数、小数精度和能量上限保持不变。UI未改。

当前源表这两类Buff都没有反应限定。未来若新增反应专属精通/充能行，需要先定义其查询上下文再接入；当前没有反应参数时不计入，不从全局历史声明推断。HPBonusFlat、DEFBonusFlat、月曜/星烁实际伤害入口等其他缺口不因本节而视为完成。星扩散按用户要求继续跳过。

## 固定防御的数值接入

511幸运儿两件套的DEFBonusFlat已接入GetFinalDEF：在已有TotalDEF与“基础防御×状态防御百分比”之后加固定防御，最终最低0。固定值不再乘百分比，也不回写面板。百分比、固定防御均走统一只读属性收集，检查来源、范围、主表/效果条件和MaxCount；Count读取来源角色，定义正确但没有实例时按0，不因查询消耗或修改数值。

原承伤及DEF倍率公式继续调用同一GetFinalDEF入口。用例代码已补充，按项目规则未运行Unity测试。该轮仅修改代码，510后续确认的开战初始化及源表改动以下节为准。

## 510与511的新版四件套

按最新Artifacts源表及用户确认，510四件套是战斗开始给全队生命上限+200，不是立即治疗200；511四件套是受到伤害降低8%。状态源表已移除旧的两条结束回血行动和Heal定义，不再由这两套监听BattleEnded。

510保留两件套451001的本人固定生命上限1000，四件套父451002在完整编队BattleReady后通过原BindStatus绑定新451003：隐藏永久、HPBonusFlat=200、MaxStack=0、MaxCount=1。不同来源真实实例都保留，数值只计一份；来源阵亡只撤自己的绑定，不误删别的来源。AdventurerArtifactHooks按净差初始化TotalHP，重复初始化不累加；原满血保持满血，非满血保持绝对血量且不超过新上限，不复活、不产生治疗或初始化获取声明。失效时撤回加成并钳制血量，重置清场撤回净差；本实现只处理510开战常驻属性，不扩大为所有临时生命Buff。

511四件套451102配置为Buff/DMGTaken/-0.08，进入受击方承伤区，同区先加算，无其他修正时乘0.92；最终反应与暴击之后、护盾及扣血之前由HitBatch统一执行。两件套固定防御100仍走GetFinalDEF，不混入该减伤区。

## 直接月曜／星烁伤害、夜魂标记及True

Damage.Param3用于Lunar、Stellar、NightSoul性质，DamageType仍保留普攻/重击/战技/爆发标签；元素组合在加载时严格校验。直接月曜三类和冰雷星烁技能伤害已走独立BaseDMGBonus、对应LunarDMGBonus/StellarDMGBonus及BaseDMGBonusFlat乘区，不使用普通DMGBonus或防御；最终暴击和DMGTaken仍只结算一次。NightSoul随真实伤害声明传递，不从角色ID反推，也不自动修改夜魂值或加持状态。
